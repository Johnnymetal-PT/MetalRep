# MIG-0008 - Ficheiro de imagem em falta no filestore

## Contexto

Durante a sessão de Click Everywhere em Odoo 18, o log do servidor registou erro ao carregar uma imagem de produto.

Na zona de Helpdesk mostrada no screenshot, os pedidos `helpdesk.team` no log retornam `200`, sem traceback. A mensagem "Não foram encontradas equipas" parece indicar ausência/configuração de equipas de Helpdesk, não erro de servidor.

## Evidência

Erro no log:

```text
FileNotFoundError: [Errno 2] No such file or directory: '/ProgGest/Odoo18/data/filestore/PRIVATE_test_18.0_2026_06_01_11_38/d5/d5eb3554af7f25a597c919c1b6f7868515a2c6a0'
```

Pedido afetado:

```text
GET /web/image/product.template/8639/image_128?unique=1780310918000 HTTP/1.1" 500
```

## Classificação

- Fase: Teste funcional
- Camada técnica: Dados/Constraints
- Severidade: S5 - Observação
- Estado: Não aplicável
- Causa raiz: RC-0007
- Estado da causa raiz: confirmed

## Modelo/campo afetado

- Modelo: `product.template`
- Registo observado: `8639`
- Campo: `image_128`

## Causa provável

A base de dados referencia anexos/imagens para `product.template` 8639, mas o ficheiro físico correspondente a pelo menos `image_128` não existe no filestore restaurado em Odoo 18.

Isto aponta para problema de dados/filestore da migração/restauro, não para erro de código custom.

## Confirmação SQL

A query a `ir_attachment` retornou 5 anexos para `product.template` 8639:

```text
image_1920
image_1024
image_512
image_256
image_128
```

O registo `image_128` tem `store_fname`:

```text
d5/d5eb3554af7f25a597c919c1b6f7868515a2c6a0
```

Esse é exatamente o ficheiro físico em falta no traceback.

## Correção proposta

Confirmar se o filestore da BD 17 foi copiado/restaurado integralmente para a BD 18.

Para identificar o anexo relacionado:

```sql
SELECT id, res_model, res_id, res_field, name, store_fname, checksum
FROM ir_attachment
WHERE res_model = 'product.template'
  AND res_id = 8639
  AND (res_field LIKE 'image%' OR store_fname = 'd5/d5eb3554af7f25a597c919c1b6f7868515a2c6a0');
```

Depois escolher uma destas opções:

- repor o ficheiro físico em falta no filestore;
- remover/regenerar a imagem do produto afetado;
- se for perda aceitável em teste, documentar como perda de imagem não bloqueante e continuar.

Se for para limpar/regenerar, considerar todos os anexos de imagem do produto 8639, não apenas `image_128`, porque os tamanhos derivados podem apontar para ficheiros diferentes.

## Decisão

O tester confirmou que o ficheiro não existe no sistema e pediu para dar como perdido.

Sem correção aplicada neste piloto. A perda da imagem foi classificada como conhecida/não bloqueante.

## Reteste recomendado

Continuar o Click Everywhere. Se surgirem outros `FileNotFoundError` de filestore, documentar como nova ocorrência ou duplicado conforme `store_fname`/modelo afetado.
