# MIG-0002 - `odoo-bin` não encontrado no servidor Linux

## Contexto

Durante a tentativa de reproduzir por comando a instalação dos módulos `pg_sale_salesperson` e `pg_tecidos` na BD Odoo 18.0, o comando `odoo-bin` não foi encontrado no terminal Linux.

## Evidência

Comando tentado:

```bash
odoo-bin -d PRIVATE_test_18.0_2026_01_11_38 -i pg_sale_salesperson,pg_tecidos --stop-after-init
```

Erro reportado:

```text
odoo-bin: command not found
```

A screenshot mostra também o serviço `odoo18` a ser reiniciado via `systemctl`, indicando que a instalação Odoo 18 provavelmente corre através de um serviço systemd com caminho/configuração próprios.

Output recebido de `systemctl cat/show`:

```text
/etc/systemd/system/odoo18.service
User=adminpg
ExecStart=/ProgGest/Odoo18/python-venv/bin/python3.10 /ProgGest/Odoo18/Server/odoo-bin -c /ProgGest/Odoo18/odoo.conf
```

Isto confirma o Python/venv, o caminho do `odoo-bin` e o ficheiro de configuração usados pelo serviço.

## Classificação

- Fase: Preparação ambiente
- Camada técnica provável: Manifest/Dependências
- Severidade: S3 - Média
- Estado: Corrigido
- Causa raiz: RC-0002
- Estado da causa raiz: confirmed

## Causa provável

O executável `odoo-bin` não está no `PATH` do utilizador `adminpg`. A instância Odoo 18 está instalada como serviço `odoo18`, correndo como `User=adminpg` e usando diretamente o Python do venv:

```text
/ProgGest/Odoo18/python-venv/bin/python3.10 /ProgGest/Odoo18/Server/odoo-bin -c /ProgGest/Odoo18/odoo.conf
```

## Correção proposta

Usar diretamente o comando real do serviço e acrescentar a BD, os módulos e `--stop-after-init`:

```bash
/ProgGest/Odoo18/python-venv/bin/python3.10 /ProgGest/Odoo18/Server/odoo-bin \
  -c /ProgGest/Odoo18/odoo.conf \
  -d PRIVATE_test_18.0_2026_01_11_38 \
  -i pg_sale_salesperson,pg_tecidos \
  --stop-after-init
```

Se o terminal reportar erro de permissões, executar com o utilizador do serviço:

```bash
sudo -u adminpg /ProgGest/Odoo18/python-venv/bin/python3.10 /ProgGest/Odoo18/Server/odoo-bin \
  -c /ProgGest/Odoo18/odoo.conf \
  -d PRIVATE_test_18.0_2026_01_11_38 \
  -i pg_sale_salesperson,pg_tecidos \
  --stop-after-init
```

## Reteste recomendado

Executar o comando acima e colar o traceback/log completo. Esse output deve revelar o erro real de instalação documentado no `MIG-0001`.
