## O que limpar primeiro, mantendo o visual igual

### Prioridade 1

Congelar o estado atual e externalizar a lógica visual ativa para uma estrutura controlada, sem alterar output:

1. replicar o CSS atual em ficheiro versionado
2. manter a mesma ordem de carregamento
3. validar página a página antes de remover o `custom_code_head`

### Prioridade 2

Separar o CSS em blocos estáveis:

1. design tokens
2. base tipográfica
3. layout/header/footer
4. catálogo/listagem
5. página de produto
6. hotfixes utilitários
7. responsive

### Prioridade 3

Reduzir propagação global sem mexer no render:

- substituir seletores demasiado largos por seletores de contexto
- reduzir `!important` apenas onde a cascata já estiver estabilizada
- remover duplicações evidentes de footer, breadcrumb e product title

## Riscos já identificados

- `392` usos de `!important` indicam forte dívida de especificidade
- existe override global de `h2`, com alto risco de efeito lateral
- há regras muito largas sobre `div`, `span`, `.container`, `.row`, `.card`
- há assets `_custom/...` ativos, o que significa que o painel do website pode voltar a sobrescrever parte da organização se não controlarmos a origem final das regras

## Conclusão operacional

Para a tarefa 6604, a intervenção correta não começa por “limpar módulos” em abstrato.
O primeiro alvo deve ser o styling ativo em produção que hoje vive em:

1. `website.custom_code_head`
2. `/_custom/.../user_custom_rules.scss`
3. assets de variáveis do theme/website

Só depois faz sentido consolidar o CSS do produto e os ajustes já existentes nos módulos locais.
